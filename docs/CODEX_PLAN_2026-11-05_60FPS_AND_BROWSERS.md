## 1. Preserve 60 fps uploads end to end

**Smallest safe contract:** one CFR export rate per job, either 30 or 60. Select the maximum source-rate bucket among video clips actually used, including the hook; 29.97 → 30, 59.94 → 60. Rates above 30 (with a small tolerance for metadata jitter) select 60; rates above 60 are explicitly capped. Slow motion does not synthesize frames. 59.94 → 60 is cadence normalization, not exact timestamp preservation. Keep timeline data in seconds and the existing cumulative frame rounding. Do not simply change the global default to 60: that doubles work for 30 fps projects.

Assert 120 frames for a two-second 60 fps export and distinct consecutive source frames at speed 1; a 60 fps header with duplicated 30 fps pictures fails. ## 2. Browser export in Safari 17+ and Firefox 130+

**Do not ship by deleting the UA check.** `browserExportSupported` currently requires Chromium brands, native `AudioEncoder`, OffscreenCanvas WebGL2, AVC and AAC. Mediabunny muxes MP4 and wraps codecs; it does not automatically supply missing codecs.

| Requirement | Safari 17+ | Firefox 130+ |
| --- | --- | --- |
| WebCodecs video | Video APIs predate 17; AVC configuration still requires real device trials. | 130 introduced desktop WebCodecs; this is not a promise for Firefox Android or every OS codec. |
| AVC quantizer mode/per-frame QP | Do not assume the Chromium QP20 lane works through VideoToolbox. Probe exact config and trial encode; a bitrate lane needs independent quality approval. | Do not assume QP mode works through its platform encoder. Probe/trial; test Windows and macOS independently. |
| OffscreenCanvas WebGL2 | WebGL support arrived in 17; WebKit documents a WebGL1/WebGL2 context bug fixed in 17.4. Test 17.0 separately. | Available in principle; GPU/driver/policy can still deny a context. |
| AAC `AudioEncoder` | Safari 17 lacks WebCodecs audio; AudioEncoder/AudioDecoder arrived in Safari 26. Native AAC can be used on newer versions after probing. | AudioEncoder presence does not mean AAC: native WebCodecs AAC encoding is unsupported. Needs a browser-side AAC encoder. |
| `VideoFrame` from canvas | Test actual OffscreenCanvas/WebGL output capture, texture upload and orientation; API presence is insufficient. | Same: test this app's CanvasSource path, not only a synthetic raw-buffer frame. |
| Backend | VideoToolbox on Apple platforms; no guarantee of Chrome/Windows rate control or colour behavior. | Windows Media Foundation versus macOS VideoToolbox/platform paths can differ; Linux is a separate capability/test target. Requested acceleration labels do not identify the implementation. |

Sources: [WebKit Safari 17](https://webkit.org/blog/14445/webkit-features-in-safari-17-0/), [17.4 fixes](https://webkit.org/blog/15063/webkit-features-in-safari-17-4/), [Safari 26 audio](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/), [Firefox 130 release notes](https://developer.mozilla.org/en-US/docs/Mozilla/Firefox/Releases/130), [MDN codec selection](https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API/Codec_selection). Backend names are test distinctions, not evidence of the encoder actually selected.

**Real-machine gate:** test actual Safari 17.0 and 17.4+ on compatible macOS, Intel and Apple Silicon where available, plus current Safari; include real iPhone/iPad Safari 17 if the “Safari 17+” claim includes mobile. Test Firefox 130 and current Firefox on Windows (integrated GPU, including an 8 GB laptop) and macOS; qualify Linux separately. Playable MP4 does not prove AVC encoding or HEVC input decoding. Test real iPhone HEVC/rotation/VFR and SDR AVC inputs, silent clips, multiple sound layers, captions, mixed rates, demo extraction, 18/60/180-second runs, backgrounding, peak memory, cancellation and repeat exports. Inspect frame counts, audio priming/sync, final flush, container/VUI colour agreement and QuickTime/iPhone/Windows playback; measure moving-video A/B and worst-window quality against aligned references. Test HDR only after Claude's work is merged, with no assumed browser colour equivalence.

**Ship only when** the advertised minimum-version/device matrix completes real exports with approved quality, intact audio/demo/timing, acceptable measured memory/time, and zero automatic server fallback. Runtime probes must still reject unsupported devices. If 17.0 or Firefox 130 cannot pass, keep that combination disabled and narrow the published minimum; support on today's browser cannot substantiate “17+/130+.” Release browser coverage and 60 fps independently, then test their intersection before advertising 60 fps on those browsers.
